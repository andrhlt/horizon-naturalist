# Current-nightly development notes

The root project targets Horizon `0a875da91dbb0fdcb7ba8c42c11341aa229af51a` and Minecraft 26.3. It has been built and opened headlessly, including alongside Wildlife Tuning. This remains an incomplete migration, not a release or a gameplay parity claim. The legacy 0.7.4-preview.45 implementation and its launcher helpers are preserved on `main`.

`python3 tools/package_current.py <original-jar> <output.hmod>` packages the root project deterministically. `python3 tools/refresh_current_data.py <original-jar>` checks generated content against the tracked root data; `--write` regenerates the full generated set, while `--write-ant-worldgen` refreshes only Ant's two configured features, two placed features and 24 structure templates before a native build. The original jar is identified by its exact SHA-512 and remains external. The tracked data files are generated Horizon definitions, spawn modifiers, and conventional biome tags. Content definitions omit attributes unsupported by their placeholder templates; `README-omitted-attributes.txt` records them, and native declarations restore their values. Regenerate native metadata and attribute tables from `migration/entity-metadata.json` with `python3 migration/generate_metadata.py` and format the resulting Rust files.

The current build registers 51 entity IDs and 146 items. Those item defaults matched the supplied Java fixture for stack size, durability, rarity, and food. A headless diagnostic run matched all 48 supplied mob profiles for category, dimensions, and the eight attributes those fixtures record; other attributes remain unverified. Generated biome spawns matched all 515 rows recorded by the supplied Java fixture, including 396 Naturalist rows, their category, weight and group size. Ground placement is registered for Deer and 18 species sharing its Java animal rule; other species' spawn predicates still need their own ports.

Partial Bass rendering, hunting, schooling and bucket handling, Deer rendering, goals, variants and breeding, and capture-net interactions for selected species, including owned and wild Ants, have been implemented and tested in development fixtures. Those tests do not establish full species parity. Natural Ant hill generation uses supported Horizon `minecraft:template` features. The focused headless fresh-world seed-42 fixture passed on pinned candidate `native-0a875da-5e28db547bcd`, checking both hill sizes, functional queen/entrance states, block-entity storage, wild Ant entry and save/reopen; see [`ant-natural-5e28db547bcd.json`](../fixtures/ant-natural-5e28db547bcd.json). Template rotation is constrained to `none` to preserve custom block states. Fixed-seed Java layout/RNG parity is not claimed. An admin can also grant `/give @s naturalist:queen_ant`; using it on open ground creates a functional, owned 10-block small hill. The headless [`launcher_ant_queen.py`](../tools/launcher_ant_queen.py) fixture covers blocked placement, survival item consumption, creative retention, offhand use and owner links; a LAN guest also created a hill linked to the guest UUID. Survival acquisition of a queen ant and big-hill admin placement remain unavailable. Blocked-placement particle requests are issued by the server; their delivery and appearance have not been verified. Adult Ducks laid duck eggs and reset their timers, while ducklings laid nothing; separate controlled projectile fixtures reproduced Java hatch counts for three seeds. Ant-hill block entities initialize `Storage`, retain saved `Owner` and storage data, and drop stored stacks when removed with side effects. The original `naturalist:add_animals` modifier is unsupported; generated standard modifiers cover the recorded spawn-table fixture. Variant assignment on natural Deer spawn and untested network/reload cases remain open.

The current SDK cannot replace the generic natural-spawn finalizer where Deer needs the spawn pass random stream; custom Deer variant selection for that path remains open. Deer sprint state likewise needs a seam between navigation and movement control in an unindexed lower-crate AI function.

Owned Ants accept sugar in either hand without inheriting the Wolf's sit interaction. The headless fixture checks injured, full-health and creative use. Wolf-backed Ant, Crab and Hedgehog health defaults are restored on entity join, item configuration, spawn-egg entity data, API entity-data and command-data loading; explicit saved base values are preserved. Other entity-data reload paths remain unverified, and values saved by an earlier build are retained even if they equal the incorrect Wolf default.

Ant worker development implements gathering, carrying, hill delivery and entry. The carried food has a separate item entity with its own UUID and Ant UUID; save/reload, transfer, player pickup, destructive removal and full-storage overflow have headless regression fixtures. The four-Ant gathering fixture compares the entity-ID parity behavior observed in Java. The engine currently exposes this carried object as `minecraft:item` while live and writes `naturalist:carried_food` to disk. Ant target selection and some other Wolf-template behavior remain incomplete. These worker checks are not a full Ant parity claim.

Player item placement uses the pinned `LevelRef::block_face_sturdy(..., Up, Full)` query through the entity-place hook, and the runner now exercises player placement, replacement, support removal and a non-sturdy slab rejection. Fast SDK compilation passes; shared headless runtime, LAN, matching client/server and offscreen checks remain with APP-2135.
